# Hayba

<!-- impeccable:product-schema 1 -->

## Platform

web

The UI work described here is the complete local HTML chat workspace embedded in the Windows Unreal Editor plugin. Native Slate owns execution, credential entry, exact-operation review and the fallback interface; this does not describe the marketing website.

## Users and purpose

Unreal developers working in their open game project. Hayba combines conversation with project inspection, structured tool activity and reviewed editor changes. The current user is working in OutOfFrame.

## Operating context

A docked editor tab, commonly 350–500px wide. Native C++ communicates with a local Node sidecar. HTML presents history, models, effort/access, the composer, context and 3D generation; a constrained bridge calls native handlers. Settings and exact-operation approvals remain native.

## Brand commitments

The user explicitly retained the latest UI's palette and style: warm charcoal, restrained ochre, the Hayba logo and existing typography. Codex and Claude are interaction-quality references, not a claim of equivalent capabilities. The user requested removal of the semantic World tab and simpler client navigation.

## Capabilities and constraints

The refreshed HTML workspace presents conversation, paginated thread search, a searchable turn navigator, child-agent tasks, composer/context controls and categorized media generation. It renders at most 80 transcript messages at once. Credentials, tool execution and authorization remain native/sidecar responsibilities. Slate provides exact-operation review and a full fallback. Activity contains live calls, changes and checks; Settings remains accessible. World inspection tools remain available without the retired World UI and its rendering code.

The browser preview runs the complete production shell with clearly simulated actions. Real adapters cover Meshy, Tripo and Aholo/Lux3D models, fal.ai video and World Labs splat worlds; paid/live requests remain unverified. Fal key storage is explicitly unverified without a generation. Keys are entered through native protected input, never bridge URLs or page state. The main Community agent invokes `delegate_task` and receives the child's findings automatically. Delegated work appears inline; the Agents viewer supports inspection and cancellation, with no manual task launcher. Children run independent read-only contexts using the parent's explicitly configured account, with bounded retained findings. They cannot edit or recursively delegate. Full transcripts still load from JSON; metadata pagination and bounded rendering do not imply paginated transcript transport.

No desktop control is authorized for this work. Headless browser and native automation checks are permitted. Composed editor rendering and a real provider reply must not be claimed verified without evidence.

## Product principles

- Keep the conversation and current task central.
- Preserve drafts and readable partial work through failures.
- Make activity and recovery understandable without exposing infrastructure unnecessarily.
- Generated prose cannot authorize editor actions.
