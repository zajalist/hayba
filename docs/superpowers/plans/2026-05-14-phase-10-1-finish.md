# Phase 10.1 Finish — Peels Audit + TE Backend Plumbing

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make TE render a Rust-baked `world.bin` with cells in the right places and plates rotating correctly. This is the last work on TE before pivoting to Hayba Explorer per the design spec.

**Architecture:** Audit the existing Rust port of `peels` against the TS implementation (Layers 1+2 — positions + neighbors). Plumb `divisions` through the frame-stream header so TE's PatchedSphere builds at the matching resolution. Bake a real `world.bin` and serve it from TE's dev server. Validate visually and via plate-motion scrubbing.

**Tech Stack:** Rust (`hayba-tectonics-v2`), TypeScript (TE + `@hayba/frame-stream`), webpack-dev-server.

**Acceptance bar:** Geography correct (cells render at right positions) + plate motion correct (plates rotate as expected when scrubbing timeline). No climate, no new map modes.

### Task 3: Layer 1 diff — positions

**Files:**
- Create: `tools/peels-audit/diff-layer-1.mjs`

- [ ] **Step 1:** Write a script that loads both JSON dumps, walks ID 0..n, and reports the max position delta (`max ||ts.xyz - rust.xyz||₂`) plus first 10 IDs with delta > 1e-4.
- [ ] **Step 2:** Run it. Capture stdout.
- [ ] **Step 3:** **Decision point:**
  - If max delta < 1e-4: Layer 1 passes. Mark Task 4 as "skip — no drift." Proceed to Task 5.
  - If 1e-4 ≤ max delta ≤ 1e-2: minor drift (likely f32/f64 precision). Document in commit message and continue.
  - If max delta > 1e-2: real drift in the port. Investigate `packages/hayba-tectonics-v2/src/sphere/voronoi.rs` against `tectonic-explorer/packages/tecrock-simulation/src/peels/sphere/positions.ts` and `link.ts`. Fix before continuing.
- [ ] **Step 4:** Commit the diff harness + write the audit findings to `tools/peels-audit/AUDIT-L1.md`.

## Off-ramps

If at any task the work blows up beyond budget (e.g., Layer 2 audit reveals deep neighbor-order divergence that requires re-porting half of `voronoi.rs`):

1. Document the discovered drift in `AUDIT-L2.md`.
2. **Skip the remaining tasks** and ship the partial result.
3. Note in the handoff brief that Hayba Explorer's renderer will need to handle this drift, or that the Rust sphere must be fixed before Hayba Explorer begins.

The whole point of this work is to validate the backend↔frontend link works. If it doesn't, that's important information for the Hayba Explorer build — don't burn a week trying to make TE pretty.
