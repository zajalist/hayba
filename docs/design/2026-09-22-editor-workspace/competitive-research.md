# AI editor workspaces: workflow research

Research date: 2026-09-22. Sources below are first-party documentation, product pages, or source repositories. Product claims describe the vendors' documented behavior; I did not install or independently benchmark these products. UX strengths, risks, and Hayba opportunities are my inferences from those sources.

## What competitors actually put in the workflow

| Product | Context → plan → action → result → verification | Useful lesson / limit |
| --- | --- | --- |
| **Aura (Unreal/Unity)** | `@` asset search, Content Browser drag/drop, level right-click, selection awareness, images and documents feed chat. Ask/Plan/Agent modes separate reading, editable Markdown plans with a Start action, and project mutation. The Unreal Level Design Agent plans zones, validates structure, builds editable blockout geometry, and can create PCG scatters; its verification agent claims PIE runtime inspection and recorded video. [Context](https://www.tryaura.dev/documentation/giving-aura-context/), [modes and plans](https://www.tryaura.dev/documentation/quick-start/), [level design](https://www.tryaura.dev/documentation/level-design-agent/), [verification](https://www.tryaura.dev/documentation/verification-agent/) | Strong continuity between selected editor objects, plan, action, and evidence. Its own docs call level design **alpha**, advise dedicated test levels, and list unreliable dynamic-mesh undo and large-blockout performance issues. Those caveats argue for Hayba to show scope and rollback limits before building. [Limitations](https://www.tryaura.dev/documentation/level-design-agent/) |
| **Ludus (Unreal)** | Docked chat has a service status and mode selector. For larger work, a plan panel supports accept/reject/revise; a live checklist and subagent carousel report progress. Generation, import, and project edits have distinct approvals; edits can be staged and applied in one reviewed commit. Vendor docs claim broad Blueprint, Material, PCG, audio, and asset-generation coverage. [Interface](https://docs.ludusengine.com/getting-started/plugin-interface/), [planning](https://docs.ludusengine.com/agent/planning-memory-subagents/), [approvals](https://docs.ludusengine.com/agent/approvals-safety/), [coverage](https://docs.ludusengine.com/agent/overview/) | Approvals are tied to the type of action, and a staged change set is more legible than generic “allow tool” prompts. The broad capability claims are unverified here. |
| **Coplay (Unity; now part of Aura)** | In-editor chat for scene analysis, code generation, and asset workflows; action recording teaches repeatable user-specific procedures. Its public repository says it is now Aura, so treat it as a related product lineage rather than an independent market signal. [Docs](https://docs.coplay.dev/), [repo](https://github.com/CoplayDev/coplay-unity-plugin), [product comparison](https://coplay.dev/products) | Action recording is a concrete way to capture a team's pipeline. It suggests a later Hayba “save this workflow” feature after core tasks work reliably. |
| **Unity AI Assistant** | Native editor conversation distinguishes Ask (read-only) from Agent (scene/asset edits with permission checks). Unity places generators for sprites, textures, sound, animation, materials, and terrain layers under the AI menu; assets can be used in the project. [Assistant](https://docs.unity.com/en-us/engine/6000.3/manual/packages-list/packages-all/pack-safe/com-unity-ai-assistant), [AI menu](https://docs.unity.com/en-us/engine/6000.7/manual/unity-ai/ai-menu-access), [generators](https://docs.unity.com/en-us/engine/6000.3/manual/get-started/first-time-user/getting-started-ai) | A plain distinction between inspect and act is easier to understand than many named agents. Generators are task entrypoints, not a reason to create a separate top-level destination for each asset type. |
| **Promethean AI** | Asset “braintrust” and palettes center an artist's existing library and visual references. Its first-party data page says it builds local asset metadata and learns labeled spatial relations such as object distances/bounds; its public version lists browser, palettes, search, and limited commands, while fuller scene generation is enterprise-oriented. [World building](https://www.prometheanai.com/ai-world-building), [metadata](https://www.prometheanai.com/data-collection-info), [public version](https://www.prometheanai.com/download-public) | Supports Hayba's Scene Intent Graph idea: semantic relations and spatial bounds are useful explicit data. It does **not** establish that a literal visual “5D latent space” is needed or usable. Distinguish publicly available functions from enterprise claims. |
| **Epic Unreal MCP (UE 5.8, experimental)** | Epic exposes Unreal editor toolsets through an in-process MCP server to external clients. Examples include actors, material instances, Slate inspection, and automation tests; tool search discovers toolsets on demand. Epic says the feature is experimental and incomplete. [Unreal MCP](https://dev.epicgames.com/documentation/unreal-engine/unreal-mcp-in-unreal-editor), [automation toolset](https://dev.epicgames.com/documentation/unreal-engine/API/Plugins/AutomationTestToolset/UAutomationTestToolset) | Raw editor access is becoming infrastructure. Hayba needs production intent, coherent tasks, artifact review, game-specific checks, and a polished native surface on top. Consider interoperability rather than duplicating every low-level tool. |
| **Codex app** | Project-organized threads, isolated worktrees, progress in the thread, diffs with comments, and handoff into an editor. OpenAI also describes logs/test output as evidence for completed tasks. [App](https://openai.com/index/introducing-the-codex-app/), [task evidence](https://openai.com/index/introducing-codex/) | A task should retain its plan, actions, artifacts, and evidence in one thread. Multiple agents are useful only if their output rolls up into one reviewable task. |
| **Claude Code Desktop** | Sessions hold their own context and changes. The workspace supports chat, diff, preview, terminal, file, plan, tasks, and subagent panes; attachments and `@` mentions add context. Permission modes separate plan from edits, and diff comments flow back to the agent. [Desktop docs](https://code.claude.com/docs/en/desktop) | The review surface is part of the conversation, with collapsible detail. Hayba should translate “diff” into actor/asset/scene changes rather than imitate code-only panels. |
| **Cursor** | Agent can research and produce an editable plan before building. Its chat timeline offers checkpoints; review exposes changes, while run modes control approvals. [Plan](https://cursor.com/docs/agent/plan-mode), [checkpoints](https://cursor.com/docs/agent/overview), [run modes](https://cursor.com/docs/agent/security/run-modes) | Plan, edit, review, and restore are linked. A persistent “what changed in this task” entrypoint matters more than exposing every tool call by default. |
| **Replit Agent** | A task board organizes drafts, active work, ready-for-review work, and applied work. Ready tasks expose work log, test output, and preview; Agent settings expose app testing and code review. [Task board](https://docs.replit.com/references/agent/task-board), [Agent modes](https://docs.replit.com/replitai/assistant/) | A board is useful for many parallel tasks but likely too heavy inside a 350–500 px Unreal dock. Borrow its task states and compact review bundle, not the board layout. |

## Cross-product pattern

The strongest documented loop is **capture precise project context → propose a reviewable task → perform scoped editor work → expose changed artifacts → verify the intended outcome**. Aura and Ludus show this in game editors; Codex, Claude, Cursor, and Replit make the work and result legible through task-scoped review. [Aura](https://www.tryaura.dev/documentation/quick-start/), [Ludus](https://docs.ludusengine.com/agent/planning-memory-subagents/), [Codex](https://openai.com/index/introducing-the-codex-app/), [Claude](https://code.claude.com/docs/en/desktop), [Cursor](https://cursor.com/docs/agent/plan-mode), [Replit](https://docs.replit.com/references/agent/task-board)

Native affordances matter: content browser assets, level actors, selection, outliner paths, graph assets, play-in-editor state, and editor test results should be linkable context and result objects. Aura explicitly documents Content Browser drag/drop, level right-click, and selected assets, while Epic's MCP exposes structured editor tools. [Aura context](https://www.tryaura.dev/documentation/giving-aura-context/), [Epic MCP](https://dev.epicgames.com/documentation/unreal-engine/unreal-mcp-in-unreal-editor)

## Implications for Hayba's blueprint

1. **One task surface.** Begin in a docked conversation with a visible project/level/selection context strip. A user can add actors, assets, files, images, or a region. The context strip must state exactly which selection and loaded-world scope the agent can inspect.
2. **Few mode promises.** Use Inspect, Draft, and Build/Production as behavior contracts rather than persona names. Inspect reads; Draft produces editable scene or asset proposals; Build applies approved changes and reports checks. The specialized agents route internally and appear only when a handoff matters.
3. **Typed result cards in the thread.** A scene layout, blockout, landscape import, generated asset, changed Blueprint, or validation run gets its own card with targets, proposed changes, status, and an Open/Select/Review action. Each card links to the same objects in the World view and Unreal Editor.
4. **Action-specific review.** Show an import preview before import, a scene plan before spawning actors, and a change summary before risky mutations. Approval copy names the exact asset/level and operation; failure and cancellation are visible in the card.
5. **Evidence, including gaps.** Every task ends with changed objects and checks marked passed, failed, or not checked. World Partition, unloaded actors, Nanite, collision, PIE, and performance only appear as “verified” when an actual check ran. A generic green “production ready” badge would be misleading.
6. **Scene Intent Graph as a useful artifact.** Store zones, typed object relations, bounds, references, and constraints; render a 2D map with optional 3D point samples. Use it to explain and edit a blockout. Validate placement and navigability against the loaded scene. This is a product hypothesis, not a proven capability of a latent 5D display; Promethean's spatial metadata is the closest documented precedent. [Promethean semantic data](https://www.prometheanai.com/data-collection-info)

### What to avoid

- A top-level tab for each agent/tool: it fragments a single task and makes the user move context manually.
- “Import with Agent” buttons that merely paste text into chat: the label must match the action or open a real guided proposal.
- A code-agent transcript transplanted unchanged into Unreal: actor and asset changes need visual, selectable previews.
- Hidden scope or silent success: especially for unloaded World Partition regions, generated geometry undo, and gameplay that was never run. Aura's own limitations show why these states must be explicit. [Aura level design limitations](https://www.tryaura.dev/documentation/level-design-agent/)
