# PCGExKnowledge in Hayba

Hayba can read a local [PCGExKnowledge](https://github.com/PCGEx/PCGExKnowledge) JSON bundle to answer PCGEx documentation queries. Download or clone a pinned revision of that repository, then set `HAYBA_PCGEX_KNOWLEDGE_DIR` to the directory containing `manifest.json`, `search.json`, `concepts.json`, and the plugin JSON files named by `manifest.plugins[].file`. No network access occurs while Hayba serves tools.

If the environment variable is unset, Hayba also checks `mcp-tools/hayba-mcp/Resources/PCGExKnowledge` and the workspace-root `Resources/PCGExKnowledge`. The bundle is optional. A missing, unsupported, or malformed bundle leaves `hayba_query_pcgex_docs` using its existing local node catalog and SQLite registry.

`hayba_query_pcgex_docs` searches node and concept names, aliases, purposes, situations, and concept outlines. It returns at most eight matches. Use `hayba_get_pcgex_knowledge_detail` with an exact result ID for pins, settings, warnings, inherited IDs, `see` references, or concept prose. The detail tool resolves alias class IDs and references across plugin files. Its text and collection lengths are bounded. The existing `includeSourceSnippet` option uses registry paths relative to `PCGExtendedToolkit/Source`. Set `HAYBA_PCGEX_SOURCE` to a local Source directory to opt into reading snippets; without it, catalog and SQLite metadata remain available and the result marks the snippet unavailable. Absolute, escaping, or symlinked-outside header paths are never read. When a local catalog result matches a knowledge entry, the response keeps any available local snippet and adds a `knowledge` field with the detail ID, classification, documented plugin version, source hash, and staleness signals.

Results carry the bundle generation date, format version, documented plugin version, source hash, and stale flag when available. These describe the documentation snapshot. Compare the documented plugin version with the installed `.uplugin` and use UE reflection for current pin and setting truth before creating a graph. Only entries classified as `node` or `provider` have `placeableInPcgGraph: true`; assets, shared structs, factories, Blueprint nodes, and concepts do not.

The reader accepts bundle schema 2.x from 2.0.0 onward and rejects other major versions. Pin a PCGExKnowledge commit to keep results reproducible across machines.

## Use the documentation in a production graph decision

PCGExKnowledge is reference material for candidate discovery, not a graph recipe or an assertion about the running editor. Start with the scene objective and constraints: platform, frame-time and memory budgets, streaming behavior, instance counts, texel density, deterministic regeneration, and the amount of hand correction designers need. Compare manual placement or Actor Palette, reusable composed assets, native PCG, PCGEx, and a hybrid. A specialized PCGEx node is useful only when its extra capability outweighs its version dependency and graph complexity. A broad generated field can coexist with hand-placed focal assets; define which system owns each part before a re-cook.

For a PCGEx candidate, use `hayba_query_pcgex_docs` to find a concept or class, then `hayba_get_pcgex_knowledge_detail` for pins, settings, warnings, and source provenance. Capture the bundle generation date and documented version; compare that version to the PCGEx plugin installed in the target editor. `hayba_get_pattern_template` provides a catalog-only draft with explicit class, pin, and edge checks. It does not consume PCGExKnowledge or validate the installed plugin. Check loaded classes, default pins/types, and settings with `pcg_list_node_classes` and `pcg_get_node_details` in a scratch editor. Once a graph node exists, use `pcg_list_pins` to inspect its exact current pins before wiring. Missing or stale documentation should remain an unknown until live inspection resolves it.

Validate the proposed graph with `pcg_validate_graph` before creation. Once a graph is bound to an actor, `pcg_cook_and_wait` returns post-cook per-mesh ISM counts and freshness signals. `pcg_execute_graph` only triggers components, and `pcg_read_node_output` can reflect a stale cache immediately after generation. Inspect the visible result as well as the readback. Counts alone cannot demonstrate composition, streaming cost, frame time, memory use, or texel density; measure those separately against the project's budget. The [PCG build workflow](../addons/workflows/hayba-pcg-build/SKILL.md) keeps these checks together.
