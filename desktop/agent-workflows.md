# What Hayba Desktop needs to finish an Unreal task

The Windows preview can answer a question about the open map. Ask it which lights affect the entrance and it reaches its limit. The level tool returns the map name, package path, actor count and Play in Editor state. It cannot inspect a particular light, propose a change to it or check the result. Desktop exposes one tool call per turn. Hayba already has a broader tool catalog, an agent loop and a review surface elsewhere in the repository. [Desktop turn handler](session.cjs) · [Editor bridge](main.cjs) · [Hayba agent loop and tool filtering](../mcp-tools/hayba-mcp/src/chat/agent-loop.ts) · [Unreal chat panel](../unreal/HaybaMCPToolkit/Resources/chat/index.html)

## Gaps in order of impact

| Priority | What is missing in Desktop | What a user should be able to do | Comparable workflow |
| --- | --- | --- | --- |
| 1 | Multiple project reads in one turn | Ask which lights affect the selected actor. Hayba identifies the active editor, reads the selection, looks up the relevant lights and names the objects it inspected. Stopping the task cancels further reads. | Cline connects to MCP servers, exposes their tools and lets the user verify a tool call. [Cline MCP](https://github.com/cline/cline/blob/main/docs/mcp/mcp-overview.mdx) |
| 2 | Visible project context | Attach an actor, asset, source file or log excerpt. See the exact path or selection going to the provider and remove it before sending. A project name alone gives little indication of what Hayba can see. | Aider maps source symbols and lets the model request the files it needs. [Aider repository map](https://github.com/Aider-AI/aider/blob/main/aider/website/docs/repomap.md) |
| 3 | Reviewable edits | Ask to change one light’s intensity. See the actor, property, current value and proposed value. Approve once, or decline and leave the scene alone. Start with one operation the editor can review and undo. Today “Plan a feature” fills in a prompt. | OpenCode defines distinct Plan and Build agents. Cline carries the conversation from planning into execution. [OpenCode agents](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/content/agents.mdx) · [Cline Plan and Act](https://github.com/cline/cline/blob/main/docs/core-workflows/plan-and-act.mdx) |
| 4 | A history of actions and results | Expand any step to see the target, operation, outcome and error. Reopen the conversation and distinguish a completed edit from a request that was declined, stopped or interrupted. The level-read entry in preview 4 covers one operation. | Codex exposes separate events for tool progress, command output, plan updates, file changes and completed items. [Codex app protocol](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/ServerNotificationEnvelope.ts) |
| 5 | Verification and recovery | After an approved edit, read the property back or run the appropriate Unreal check. Show the observed value or failure. Offer Undo for the supported operation and verify the restored value. File snapshots alone cannot recover an unsaved editor transaction. | Aider can run a configured test and use its failure output. Cline checkpoints can compare and restore project files. [Aider testing](https://github.com/Aider-AI/aider/blob/main/aider/website/docs/usage/lint-test.md) · [Cline checkpoints](https://github.com/cline/cline/blob/main/docs/core-workflows/checkpoints.mdx) |
| 6 | Continuity between the app and the editor | Start a task in Desktop and open the same transcript, attached objects and pending review in Unreal. An approval made on one surface must resolve on both. Today the surfaces use separate conversations and provider settings. | Codex models threads, turns, project association and item updates as distinct events. [Codex app protocol](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/ServerNotificationEnvelope.ts) |

## Everyday friction

- **First connection.** Saving a provider stores the key and model locally. A misspelled model ID or inaccessible model is discovered on the first prompt. Offer a model picker or manual ID, an explicit connection test, and separate messages for an invalid key, unavailable model and network failure. [Provider form](preferences.jsx) · [Settings persistence](main.cjs)
- **Returning to a project.** Search matches conversation titles derived from the first message. Users cannot name a chat, archive a finished task or find a conversation by an asset mentioned later. Add renaming, project grouping and transcript search. [Conversation list and search](workspace.jsx)
- **Long BYOK sessions.** Desktop sends previous completed turns with the next message. It shows neither token usage nor how close the conversation is to the model’s context limit. Show provider-reported usage where available and let people review a summary before continuing a long task. [Desktop turn handler](session.cjs) · [Codex token and compaction events](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/ServerNotificationEnvelope.ts)

## First end-to-end acceptance task

Open a disposable Unreal level containing two named lights. From Desktop, inspect both lights in one request and propose a change to one. Decline once and confirm both values stay the same. Approve the second request, read back both values, undo the change and read them back again. Open the same task in the editor and verify its history. This exercises tool use, project identity, review, execution, verification and recovery with a result anyone can check in the Details panel.

Existing Hayba work covers parts of this path. Coordinate cancellation and reconnect behavior with [issue #382](https://github.com/zajalist/hayba/issues/382), multi-step recovery with [issue #384](https://github.com/zajalist/hayba/issues/384), and requests that need user input with [issue #11](https://github.com/zajalist/hayba/issues/11).
